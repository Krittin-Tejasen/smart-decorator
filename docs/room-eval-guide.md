# คู่มือทดสอบ: generate ห้องจากสินค้า IKEA แล้ววัด product matching

เอกสารนี้ใช้ส่งต่อให้ Claude อีกเครื่องทำงานในทิศทางเดียวกัน ให้ Claude อ่านเอกสารนี้ทั้งหมดก่อนเริ่มงาน และทำตาม "กติกาที่ต้องทำตาม" ทุกข้อ

## 1. เป้าหมาย

ทดสอบว่า **Muse Image สร้างภาพห้องที่มีเฟอร์นิเจอร์จาก dataset ของเราได้เหมือนต้นฉบับไหม และเมื่อเอาภาพนั้นไปผ่านระบบของแอป (segment แล้วค้นหาสินค้า) จะหาสินค้าตัวที่ถูกเจอไหม**

ที่ต้อง generate จากสินค้าใน dataset เพราะเราจะรู้ว่าแต่ละชิ้นในภาพคือสินค้าตัวไหน จึงมีเฉลย (ground truth) ให้เทียบ ต่างจากการทดสอบแบบเดิมที่ใช้ห้องซึ่งไม่ใช่สินค้า IKEA จริง

ขอบเขตที่ตกลงกันแล้ว:
- **ภาพตั้งต้น:** ใช้ภาพห้องจริง (ห้องว่างหรือห้องก่อนแต่ง) เหมือนที่ผู้ใช้อัปโหลดในแอป
- **ขั้นตอน:** ใช้แบบเดียวกับแอป (`run_generate_room` ใน `backend/generation.py`) คือ composer ของแอปเขียน prompt, Muse Image สร้างภาพ และ critic ของแอปตรวจและสั่ง generate ใหม่ได้สูงสุด 2 ครั้ง
- **สิ่งที่ต่างจากแอปมีจุดเดียว:** เฟอร์นิเจอร์ต้องมาจาก dataset ทุกชิ้น
- **การสร้างภาพ:** ใช้ **Muse Image (`meta/muse-image` ผ่าน OpenRouter) เท่านั้น**
- **Gemini:** ใช้แค่ composer และ critic ซึ่งเป็นงานข้อความ ไม่ได้สร้างภาพ
- **ไม่ทำ feature extraction:** ใช้ `FEATURE_PROVIDER=none`

## 2. ผลรอบล่าสุด (อ้างอิง)

รอบ `app-pilot`: ห้องจริง 5 ห้อง เฉลย 25 ชิ้น

| วัดอะไร | ผล |
|---|---|
| Muse วาดเหมือนต้นฉบับ | 25/25 cutout |
| สินค้าที่ตัดออกมาได้ | 23/25 |
| ระบบเดาประเภทถูก | 56% |
| ค้นแบบแอปจริง: สินค้าที่ถูกติด 5 อันดับแรก | 2/25 (8%) |
| ค้นโดยบอกประเภทที่ถูก: ติด 5 อันดับแรก | 32% |

ข้อสรุป:
- **การสร้างภาพใช้ได้แล้ว**
- **ปัญหาอยู่ที่การเดาประเภท:** มักสลับกับหมวดใกล้กัน เช่น chair กับ armchair หรือตู้แต่ละแบบ
- **และอยู่ที่การค้นหาด้วยภาพ (CLIP):** index มีภาพเดียวต่อสินค้า จึงเทียบกับเฟอร์นิเจอร์ที่ถ่ายจากมุมเฉียงในห้องได้ไม่ดี

## 3. สิ่งที่ต้องมีในเครื่อง

- **Branch:** `feature/ikea-room-eval` แตกมาจาก `feature/catalog-rebuild` และใช้ catalog v2
- **โค้ด:**
  - `backend/scripts/room_eval.py`: ทุกขั้นตอน
  - `backend/scripts/room_eval_metrics.py`: ส่วนคำนวณ
  - `backend/tests/test_room_eval.py`
- **`backend/.venv`:** ติดตั้ง `requirements.txt` และ `sam2` แบบ CPU ได้ ดาวน์โหลด checkpoint `backend/checkpoints/sam2.1_hiera_small.pt` ตาม README
- **`backend/.env` ต้องมีค่าต่อไปนี้** (ห้ามพิมพ์ค่าคีย์ออกมาในแชต):
  - `CATALOG_TABLE=ikea_furniture_v2`
  - `PINECONE_INDEX_NAME=ikea-products-v2` (ต้องใช้คู่กับตาราง v2 เพราะ id ของ v1 และ v2 ต่างกัน)
  - `OPENROUTER_API_KEY` และ `OPENROUTER_MODEL=meta/muse-image`
  - `GEMINI_API_KEY` สำหรับ composer และ critic
  - `SUPABASE_URL`, `SUPABASE_SECRET_KEY` และ `PINECONE_API_KEY`
- **ทดสอบ:** `cd backend; .venv\Scripts\python -m unittest discover -s tests` ต้องผ่านทั้งหมด
- **บน Windows:** ตั้ง `PYTHONIOENCODING=utf-8` เวลารันสคริปต์ เพราะชื่อสินค้ามีตัวอักษรภาษาอื่น

## 4. ขั้นตอน

รันจากโฟลเดอร์ `backend/` ทุกขั้นรันต่อจากจุดเดิมได้ ผลทั้งหมดอยู่ที่ `backend/eval_out/rooms/<run>/` ซึ่ง git ไม่ track

### 4.1 เตรียม (`prepare`): ยังไม่มีการสร้างภาพ

```
python -m scripts.room_eval prepare --run <ชื่อรอบ> --composer \
  --photos "<โฟลเดอร์ภาพห้อง>" \
  --room-types living_room,home_office,bedroom,dining_room,living_room \
  --seed <เลข> --exclude-run pilot --exclude-run app-pilot
```

- **ประเภทห้อง:** ใส่ 1 ค่าต่อ 1 ภาพ เรียงตามชื่อไฟล์ ใช้ค่าเดียวกับแอป คือ `living_room`, `bedroom`, `dining_room` และ `home_office` ส่วน `kitchen` ทดสอบไม่ได้ เพราะระบบ matching ไม่มีหมวดของในครัว
- **ลำดับไฟล์:** บน Windows เรียงชื่อไฟล์แบบไม่สนตัวพิมพ์เล็กใหญ่ ให้เช็กลำดับใน manifest ทุกครั้ง
- **สไตล์และสี:** วนชุดสไตล์และสีของแอปทั้ง 9 แบบให้อัตโนมัติ
- **การคัดตัวเลือก:**
  1. ระบบเลือกประเภทเฟอร์นิเจอร์ที่เข้ากับห้อง 6 ประเภท
  2. กรองสินค้าที่ใช้เป็นเฉลยได้ คือมีชื่อภาษาอังกฤษ ชื่อระบุประเภทจริง และไม่ใช่อะไหล่ ของกลางแจ้ง หรือชุดรวม
  3. ให้ CLIP เทียบภาพสินค้าใน index กับคำบรรยายสไตล์และสีของแอป แล้วเอาประเภทละ 2 ชิ้นที่ใกล้ที่สุด ได้ห้องละ 12 ตัวเลือก
- **Composer:** composer ของแอปเห็นภาพห้องและรายการตัวเลือก แล้วเลือกใช้เองเท่าที่ห้องเหมาะ ไม่เกินประเภทละ 1 ชิ้น ชิ้นที่เลือกคือเฉลย
- **`--exclude-run`:** ใส่ทุกรอบเก่า เพื่อไม่ให้ใช้สินค้าซ้ำกับรอบก่อน

**สิ่งที่ต้องทำต่อจาก `prepare`:**
- ทำหน้าพรีวิวให้ผู้ใช้ดูก่อน generate แสดงต่อห้อง:
  - ภาพห้อง ประเภทห้อง สไตล์ และสี
  - ตัวเลือก 12 ชิ้น พร้อมระบุชิ้นที่ composer เลือก
  - prompt ฉบับเต็ม
  - ลำดับภาพที่จะส่งให้ Muse (ภาพห้องก่อน แล้วตามด้วยภาพสินค้า)
- **รอผู้ใช้อนุมัติก่อนทุกครั้ง**

**ถ้าผู้ใช้อยากปรับ:**
- **สีของสินค้าไม่เข้ากับห้อง:** ใช้ `reprepare --room <id> --color-weight 1 --composer` ซึ่งคัดตัวเลือกใหม่เฉพาะห้องนั้น โดยให้น้ำหนักสีเพิ่ม
- **composer เลือกของน้อยไป หรือไม่เลือกของสีที่ต้องการ:** ใช้ `recompose --room <id> --note "<คำสั่งเพิ่ม>"` ซึ่งใช้ตัวเลือกเดิมและเติมคำสั่งให้ composer คำสั่งนี้ถูกบันทึกใน manifest (`composer_note`) และต้องระบุในรายงานว่าห้องนั้นได้คำสั่งที่แอปจริงไม่มี
- ทั้งสองคำสั่งใช้ได้เฉพาะห้องที่ยังไม่ได้ generate

### 4.2 สร้างภาพ (`generate`): มีค่าใช้จ่าย

```
python -m scripts.room_eval generate --run <ชื่อรอบ> --max-usd 1 --limit 1
```

- **ทำห้องแรกห้องเดียวก่อน:** แล้วให้ผู้ใช้ดูภาพเทียบกับภาพห้องเดิม และดู verdict ของ critic ใน `generation.json` ก่อน
- **ห้องที่เหลือ:** generate เมื่อผู้ใช้สั่งเท่านั้น โดยรันคำสั่งเดิมแต่ไม่ใส่ `--limit`
- **ค่าใช้จ่าย:** Muse ประมาณ $0.01 ต่อครั้ง ห้องละ 1–3 ครั้งรวม retry ของ critic
- **ภาพที่ใช้ทดสอบ:** มีแค่ภาพสุดท้ายของแต่ละห้อง (`rooms/<id>.png`) ส่วนภาพที่ไม่ผ่าน critic เก็บไว้เป็น `<id>_attemptN.png`
- **ข้อจำกัดของ critic:** ตรวจแค่โครงสร้างห้อง ไม่ได้ตรวจว่าสินค้าเหมือนต้นฉบับ

### 4.3 ตัดภาพ (`segment`): ไม่มีค่าใช้จ่าย

```
GEMINI_API_KEY= python -m scripts.room_eval segment --run <ชื่อรอบ>
```

- **ตั้งคีย์ Gemini ให้ว่างเฉพาะขั้นนี้:** เพื่อไม่ให้ระบบ fallback ไปใช้ Gemini
- **ถ้า SAM 2 ใช้ไม่ได้:** สคริปต์จะหยุดเอง
- **เวลา:** ใช้ราว 30 วินาทีต่อห้องบน CPU (ห้องแรกนานกว่านี้เพราะโหลดโมเดล)

### 4.4 คนตรวจ cutout (`review`)

```
python -m scripts.room_eval review --run <ชื่อรอบ>     # เปิด http://127.0.0.1:8765/
```

ผู้ใช้เป็นคนตรวจเอง **Claude ห้ามตอบแทน** สำหรับแต่ละ cutout ผู้ใช้จะตอบ 2 ข้อ:
1. cutout นี้คือสินค้าตัวไหนในห้อง หรือไม่ใช่ตัวไหนเลย
2. วาดเหมือนต้นฉบับไหม: เหมือน, เพี้ยน หรือไม่แน่ใจ

เกณฑ์ที่ตกลงกันไว้:
- **ของหายบางส่วนเพราะ segment:** ตัดสินจากส่วนที่ยังเห็น
- **สีเปลี่ยนนิดหน่อยเพราะแสง:** นับว่าเหมือน
- **cutout ที่เป็นผนังหรือพื้นแทนตัวสินค้า:** ตอบว่า "ไม่ใช่ตัวไหนเลย"
- **วิธีเปิดหน้าเว็บ:** ให้เปิดใน Chrome หรือ Edge เพราะการเปิดผ่านแผงภายใน VS Code อาจขึ้นข้อความ "Paused due to Notification"

### 4.5 ค้นหาและคำนวณ

```
python -m scripts.room_eval match --run <ชื่อรอบ>          # รันได้หลังตรวจครบเท่านั้น
python -m scripts.room_eval equivalents --run <ชื่อรอบ>
```

`match` ค้นแต่ละ cutout 2 แบบ ทั้งสองแบบค้นจากสินค้าทั้งหมดใน catalog:
- **ค้นแบบแอปจริง:** ใช้ประเภทที่ระบบเดาจากชื่อของ detector
- **ค้นโดยบอกประเภทที่ถูก:** ใช้หมวดของสินค้าใน catalog เป็นตัวกรอง ใช้ในการทดสอบเท่านั้น เพื่อดูว่าถ้าระบบเดาถูกจะหาเจอแค่ไหน

### 4.6 คนประเมินด้วยสายตา (`judge`) และตรวจหมวด (`typecheck`)

```
python -m scripts.room_eval judge --run <ชื่อรอบ>       # http://127.0.0.1:8766/
python -m scripts.room_eval typecheck --run <ชื่อรอบ>   # http://127.0.0.1:8767/
```

- **`judge`:** ผู้ใช้ดูผล 5 อันดับแรกของการค้นแบบแอปจริง (สลับลำดับไว้ ไม่แสดง score ชื่อสินค้า หรือเฉลย) แล้วเลือกใบที่ตรงหรือคล้ายที่สุด และบอกว่าตรงเป๊ะหรือคล้าย ถ้าไม่มีใบไหนใช้ได้ ให้ตอบว่าไม่มี
- **`typecheck`:** ผู้ใช้ยืนยันหมวดที่ถูกต้องของสินค้าเฉลยแต่ละชิ้น เพราะหมวดใน catalog ผิดได้ เช่น storage bench ถูกเก็บเป็น `bench`
  - หมวดที่ผู้ใช้ยืนยันใช้ตัดสินว่าระบบเดาประเภทถูกไหม
  - การค้นยังต้องใช้หมวดใน catalog เพราะสินค้าถูกเก็บไว้ในหมวดนั้น

### 4.7 รายงาน

```
python -m scripts.room_eval report --run <ชื่อรอบ>     # report.md, metrics.json, results.json
```

ส่วนที่ยังไม่ได้อยู่ใน repo (ขอจากเครื่องที่ทำรอบ `app-pilot`):
- **หน้ารายงาน artifact**
- **การทดลองเพิ่มเติม:** ค้นด้วย crop ที่ไม่ลบพื้นหลัง, ค้นด้วยภาพอย่างเดียวไม่ระบุประเภท และเก็บภาพผลค้นหาของทุกแบบ

รายงานควรมีส่วนต่อไปนี้:
- ข้อสรุปตอบเป้าหมาย
- ตารางว่าสินค้าแต่ละชิ้นหลุดที่ขั้นไหน: ตัดไม่ออก / เดาประเภทผิดแต่ถ้าเดาถูกจะเจอ / เดาผิดและถึงเดาถูกก็หาไม่เจอ / เดาถูกแต่ค้นไม่เจอ / เจอใน 5 อันดับแรก
- ตาราง "ระบบเห็นแต่ละชิ้นเป็นอะไร" ที่แสดงชื่อจาก detector, รหัสหมวดที่แอปค้น (`furniture_type`) และหมวดที่ผู้ตรวจยืนยัน (ใช้รหัสภาษาอังกฤษของระบบ และใส่คำแปลไทยตัวเล็กไว้ใต้รหัส)
- ผลทีละห้อง: ภาพห้องจริงคู่กับภาพที่สร้าง สินค้าเฉลย prompt และทุก cutout พร้อมผลค้นหา 5 อันดับแรก
- คำอธิบายสั้น ๆ ตรงทุกจุดที่ใช้คำว่า "ค้นแบบแอปจริง" และ "ค้นโดยบอกประเภทที่ถูก"
- ข้อจำกัด

## 5. กติกาที่ต้องทำตาม

1. **ห้ามใช้เงินโดยไม่ถาม:** ก่อน `generate` ต้องให้ผู้ใช้ดูพรีวิวและอนุมัติ และทำห้องแรกห้องเดียวก่อนเสมอ
2. **สร้างภาพด้วย Muse Image เท่านั้น:** ไม่ใช้ Gemini สร้างภาพ และไม่ทำ feature extraction
3. **ห้ามแก้ `generation.py` หรือโค้ดของแอปเพื่อให้ผลดีขึ้น:** สคริปต์ดึง prompt, เงื่อนไขโครงสร้างห้อง และ critic ของแอปมาใช้ตรง ๆ
4. **งานตัดสินของคนให้ผู้ใช้ทำเท่านั้น:** `review`, `judge` และ `typecheck` Claude ห้ามตอบแทน และห้ามให้ผู้ตรวจเห็นผลค้นหาก่อนตรวจ
5. **ห้ามเปลี่ยนเฉลยของห้องที่ generate แล้ว:** ถ้าจะเปลี่ยนสินค้า ให้ทำรอบใหม่ด้วย `--run` ชื่อใหม่
6. **พูดตัวเลขตามจริง:** บอกขนาดตัวอย่างและช่วงความเชื่อมั่นเสมอ ห้ามสรุปว่า "ใช้ได้" จากตัวอย่างไม่กี่ห้อง
7. **ระบุทุกจุดที่ต่างจากแอปจริงในรายงาน:** เช่นคำสั่งเพิ่มของ composer หรือการให้น้ำหนักสี

## 6. ข้อควรรู้ที่เจอมาแล้ว

- **หมวด `bookshelf`:** ครอบคลุมชั้นวางของตั้งพื้นทุกชนิด ไม่ใช่แค่ชั้นหนังสือ ส่วนชั้นที่ยึดผนังคือ `wall_shelf`
- **ระบบไม่มีบางหมวด:** เช่น "storage bench" หรือที่เก็บของปลายเตียง ให้ผู้ตรวจเลือกหมวดที่ใกล้ที่สุด แล้วบันทึกเป็นข้อค้นพบ
- **โคมไฟมีชนิดย่อย:** `floor`, `table`, `pendant`, `ceiling` และ `wall` ถ้า detector เดาชนิดย่อยผิด เช่นเรียกโคมตั้งพื้นว่า table lamp แอปจะค้นผิดชนิด
- **การตั้ง composer:** ตามกติกาของแอป สีที่ผู้ใช้เลือกใช้กับผนังและหมอน ไม่ใช่เฟอร์นิเจอร์ และ composer ถูกตั้งให้ใช้เฟอร์นิเจอร์น้อยชิ้น
- **ภาพสินค้าบางชิ้นใน catalog เป็นภาพทั้งห้อง:** Muse อาจคัดลอกของอื่นในภาพนั้นไปด้วย
- **catalog v2 มี listing ซ้ำ:** สินค้าตัวเดียวกันมีหลายภาษาหรือหลายประเทศ ขั้น `equivalents` จึงนับสินค้าที่ SKU เดียวกัน หรือภาพใน index เหมือนกัน (cosine ≥ 0.999) ว่าเป็นตัวเดียวกัน (ทดสอบแล้วว่าค่าที่ต่ำกว่า 0.999 ยังเป็นคนละสินค้า)
- **ภาพหลายมุมต่อสินค้า:** ข้อมูลดิบที่ scrape มามีคอลัมน์ `image_urls` (เฉลี่ยประมาณ 4 ภาพต่อสินค้า) แต่ `clean_catalog.py` เก็บไว้แค่ `main_image` นี่คือทางปรับปรุงการค้นหาที่น่าลองต่อ
